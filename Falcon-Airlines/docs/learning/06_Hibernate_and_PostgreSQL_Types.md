# Hibernate and PostgreSQL Types

## What we implemented

- `Instant` and `LocalDate` for `TIMESTAMPTZ` and `DATE`.
- `BigDecimal` for `DECIMAL` amounts.
- `@Enumerated(EnumType.STRING)` for all `status`, `gender`, `risk_level` columns.
- `@JdbcTypeCode(SqlTypes.JSON)` for `JSONB` columns (`configuration`, `factors`, `old_values`, `new_values`).
- `@JdbcTypeCode(SqlTypes.ARRAY)` for PostgreSQL arrays (`ssr_codes`).
- `@CreationTimestamp` and `@UpdateTimestamp` for audit columns.
- `@SQLRestriction("is_deleted = false")` for soft-delete filtering.

## Why

Hibernate 6 maps Java types to PostgreSQL types without extra converters. Using the right type keeps the domain model safe and the database efficient.

## Important annotations

```java
@Enumerated(EnumType.STRING)
@Column(name = "status", nullable = false, length = 20)
private UserStatus status;

@JdbcTypeCode(SqlTypes.JSON)
@Column(name = "configuration", columnDefinition = "jsonb")
private String configuration;
```

## Common interview questions

1. **How do you map PostgreSQL JSONB in JPA?**  
   Use `@JdbcTypeCode(SqlTypes.JSON)` on a `String` or DTO and let Hibernate handle the serialisation.

2. **What is the difference between `@Column(nullable = false)` and `NOT NULL`?**  
   `nullable = false` is a Hibernate validation; the database constraint is created by the schema (Flyway).

3. **Why use `GenerationType.IDENTITY` with PostgreSQL?**  
   It matches `BIGSERIAL` / `GENERATED BY DEFAULT AS IDENTITY` and lets the database assign the primary key.

## Best practices

- Keep entity state changes inside a `@Transactional` boundary.
- Prefer `ddl-auto: none` and own the schema with Flyway in production.
- Use `@JdbcTypeCode` for vendor-specific types instead of custom converters where possible.
